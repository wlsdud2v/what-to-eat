# 오늘 뭐 먹지? 🍚

현재 위치의 **날씨·계절·지역 특산**과 **점심/저녁**을 반영해 메뉴를 추천하고, 그 메뉴를 파는 **주변 식당을 카카오맵과 목록**으로 보여주는 웹 앱입니다.
지도·식당 검색·위치 검색·주소 변환은 모두 **카카오맵 JavaScript SDK**를 쓰고, 카카오 키가 없거나 SDK 를 못 불러오면 OpenStreetMap(Leaflet·Overpass)으로 자동 대체됩니다.

## 카카오 키 설정

1. [Kakao Developers](https://developers.kakao.com) → 내 애플리케이션 → 앱 만들기
2. **앱 → 플랫폼 키 → JavaScript 키 → JavaScript SDK 도메인** 에 등록: `http://localhost:8000`, `https://wlsdud2v.github.io`
   - 경로(`/what-to-eat/`)·끝 슬래시 없이 **출처만** 적습니다. 등록 안 된 도메인이면 카카오가 SDK 요청을 401(domain mismatched)로 거부해 OSM 지도로 대체됩니다.
   - ⚠️ **제품 링크 관리 → 웹 도메인** 은 카카오톡 공유 링크용이라 여기에 넣으면 지도가 동작하지 않습니다.
3. **제품 설정 → 카카오맵** 사용 설정 ON
4. 같은 **JavaScript 키**를 `config.js` 의 `window.KAKAO_JS_KEY` 에 붙여넣기 (REST API 키 아님)

JavaScript 키는 등록한 도메인에서만 동작하므로 정적 호스팅에 그대로 올려도 됩니다.
키가 비어 있거나 SDK 로드가 실패하면 콘솔에 경고를 남기고 지도는 Leaflet + OSM 타일(필요할 때만 불러옴), 식당은 Overpass(OSM)로 대체합니다.

## 실행

위치 권한(Geolocation)은 `https` 또는 `localhost` 에서만 동작하므로 파일을 더블클릭하지 말고 로컬 서버로 여세요.

```bash
cd what-to-eat
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000
```

배포는 GitHub Pages·Netlify 등 정적 호스팅에 폴더째 올리면 됩니다.

## 화면 구성

1. **히어로** — 화면 전체에 오늘 날씨의 하늘이 깔리고(맑음·구름 조금·흐림·안개·비·뇌우·눈·무더위·한파 × 낮/밤), 위치·날씨·계절 칩과 인사말(`비 내리는 토요일 저녁,`) 아래에 추천 1위 큰 카드 + 나머지 5개 카드가 바로 보입니다. 모바일에서는 나머지 카드를 가로로 넘겨 봅니다.
   - 카드의 **♡** 를 누르면 좋아하는 메뉴로 등록/해제됩니다. 등록한 메뉴가 추천에 나오면 카드가 분홍 테두리·빛과 `💗 내 최애` 표시로 강조됩니다.
   - 카드의 **🚫** 를 누르면 그 메뉴를 추천에서 뺍니다(알림의 `되돌리기` 로 취소). 뺀 메뉴는 「내 메뉴 관리」의 추천 제외 탭에서 관리합니다.
   - **👶 아이와 함께** 버튼을 켜면 아이와 함께 먹기 어려운 메뉴(맵거나 날것·내장·술안주 중심)를 빼고 추천하고, 카드에 `👶 아이 OK` 가 붙습니다. 설정은 브라우저에 기억됩니다(`what-to-eat:kid-only:v1`).
2. **주변 식당** — 카드를 누르면 지도·목록으로 스크롤됩니다.
3. **레시피** — 주변 식당과 같은 단계의 섹션. 선택한 메뉴를 따라가고, 검색창에 요리·재료를 직접 입력해 찾을 수도 있습니다. 아래 「레시피 검색」 참고.
4. **검색 · 추천 설정** — 위치 검색, 점심/저녁, 날씨 직접 선택, 반경, 음식 종류 제외, 👶 아이와 함께 스위치(히어로 버튼과 같은 설정), 추천 제외 메뉴 관리 링크. 위치를 바꾸면 맨 위로 돌아가 새 추천을 보여줍니다.

**내 메뉴 관리 페이지** (`favorites.html`, 상단 `💗`·`🚫` 버튼) — 탭 두 개로 좋아하는 메뉴와 추천 제외 메뉴를 함께 관리합니다. `favorites.html#excluded` 로 열면 추천 제외 탭이 먼저 열립니다.

- **💗 좋아하는 메뉴** — 메뉴 이름으로 추가(600종 자동완성, 목록에 없는 이름은 직접 추가), 삭제, 🚫 로 추천 제외 탭으로 옮기기.
- **🚫 추천 제외** — 메뉴 이름으로 추가(목록에 있는 메뉴만), ↩️ 다시 추천하기, 💗 로 좋아하는 메뉴로 옮기기. 여기 있는 메뉴는 추천 카드에 나오지 않습니다.
- 한 메뉴는 두 목록 중 한 곳에만 있습니다. 다른 목록에 있던 메뉴를 추가하면 자동으로 옮겨지고, 삭제·옮기기는 모두 되돌리기 가능합니다.
- 두 탭 모두 이름·종류·키워드 검색, 종류 필터, 정렬(최근 추가·이름·종류)을 지원합니다.

저장은 브라우저 `localStorage`(`what-to-eat:favorites:v1`, `what-to-eat:excluded:v1`)라 기기·브라우저마다 따로이고, 다른 탭에서 바꿔도 바로 반영됩니다. 직접 추가한 메뉴는 `menus.js` 에 없어서 추천 카드에는 나오지 않습니다.

스크롤하면 하늘이 흐려지며 날씨별 바탕색(`--bg`)으로 자연스럽게 녹아듭니다. 낮/밤은 Open-Meteo `is_day`, 날씨를 직접 고르면 하늘도 함께 바뀝니다. `prefers-reduced-motion` 이면 애니메이션을 줄입니다.

## 사용하는 외부 서비스

| 용도 | 서비스 |
|---|---|

## 추천 점수 규칙 (`recommend.js` → `recommend()`)

| 요소 | 점수 |
|---|---|
| 지역 특산 (역지오코딩 주소에 `부산`, `춘천`, `제주` 등 포함) | +6 |
| 계절 일치 / 사계절 메뉴 / 불일치 | +3 / +1 / −1 |
| 날씨 태그 일치 (상위 2개 합산) | 비·눈 +5, 더위·추위 +4, 그 외 +2 |
| 체감 10° 이하 + 뜨거운 국물 | +3 |
| 체감 27° 이상 + 뜨거운 국물 (이열치열 메뉴 제외) | −3 |
| 체감 27° 이상 + 차가운 음식 / 15° 이하 / 8° 이하 | +3 / −3 / −6 |
| 끼니 일치 / 불일치 | +2 / −2 |
| 반경 안에 이름이 일치하는 식당 있음 / 분류만 일치 | +2.5 / +0.5 |
| 무작위 (🎲 다시 추천 때만 바뀜) | 0 ~ 2 |

점수를 매기기 전에 제외 분류, 🚫 추천 제외 메뉴(`excludeNames`), 👶 아이와 함께일 때 `kid: false` 메뉴(`kidOnly`)는 후보에서 뺍니다.

계절은 월 기준(3–5 봄, 6–8 여름, 9–11 가을, 12–2 겨울, 남반구는 반전), 끼니는 15시 이전 점심입니다.

### 추천 근거 표시

`recommend()` 는 근거를 `{ kind, icon, text, pts }` 로 남기고(기여 점수 큰 순), 카드에는 두 가지로 보여줍니다.

- **대표 근거 배지** (`basis`) — `🌧️ 날씨 추천` · `🍁 계절 추천` · `📍 지역 추천`. 지역 특산이면 지역이 우선, 아니면 날씨·계절 중 기여 점수가 큰 쪽(체감온도 가산점은 날씨에 포함). 셋 다 없으면 `🍽️ 끼니 추천`, 그것도 없으면 `🎲 오늘의 랜덤`.
- **근거 줄마다 종류 꼬리표** — 날씨(파랑)·계절(주황)·지역(보라)·근처(초록)·끼니(회색). 큰 카드는 3줄, 작은 카드는 2줄.

화면에 보이는 6개는 `pickTop()` 으로 고릅니다. 1위는 항상 점수 1위이고, 같은 분류는 최대 2개까지만 넣어 떡볶이 여러 종처럼 비슷한 메뉴가 한꺼번에 나오지 않게 합니다. 제외 설정으로 분류가 모자라면 남은 점수 순서대로 채웁니다. 카카오 키워드 점수용 상위 12개 후보도 같은 방식(분류당 최대 4개)으로 고릅니다.

## 위치 검색 (카카오)

- 검색창 입력은 먼저 **주소 검색**(`addressSearch`, 예: `춘천`, `테헤란로 152`)을 하고, 결과가 없으면 **장소 키워드 검색**(`keywordSearch`, 예: `강남역`, `코엑스`)으로 첫 결과를 씁니다. 키워드 검색은 현재 위치 근처를 우선합니다.
- 역지오코딩은 행정동(`H`)으로 화면 라벨(`서울특별시 강남구 역삼1동`)을, 법정동(`B`)으로 지도 링크용 동 이름(`역삼동`)을 만듭니다. 지역 특산 매칭에는 행정동·법정동·도로명 주소를 모두 씁니다.
- 국외 좌표는 카카오가 결과를 주지 않으므로 Nominatim 으로 대체합니다.

## 식당 검색 흐름 (카카오)

1. 위치·반경이 바뀌면 **카테고리 검색**(`FD6` 음식점)으로 가까운 순 최대 45곳을 풀로 받습니다.
2. 추천 상위 12개 메뉴는 **키워드 검색**(`kw[0]`, 음식점 카테고리 한정)을 한 페이지씩 돌려 전체 건수(`totalCount`)로 "근처에 파는 곳 N곳" 점수를 매기고 한 번 다시 정렬합니다.
3. 메뉴 카드를 고르면 그 메뉴의 키워드 검색을 3페이지(최대 45곳)까지 가져와 지도·목록에 표시합니다. 결과는 위치·반경이 바뀔 때까지 메뉴별로 캐시합니다.
4. 사용자가 카드를 직접 고른 상태면 재정렬 후에도 그 메뉴를 유지하고, 아니면 1위 메뉴를 따라갑니다.

## 식당 매칭 (`matchRestaurant()`)

- **메뉴 일치(2)**: 카카오 키워드 검색 결과 / 식당 이름에 `kw` 포함 / 카카오 분류(`음식점 > 한식 > 해장국`)의 세부 분류에 `kw` 포함
- **비슷한 종류(1)**: 카카오 2단계 분류가 메뉴 분류와 같음(`KAKAO_GROUPS`), 또는 OSM `cuisine` 태그 일치
- 카카오 검색은 한 검색당 최대 45건까지만 주므로, 더 많은 결과는 카카오맵·네이버지도 링크로 확인합니다.

## 레시피 검색 (`recipes.js`)

- 검색어는 선택한 추천 메뉴 이름(`설렁탕·곰탕` → `설렁탕`)입니다. 검색창을 직접 고치면 자동 재추천이 일어나도 그대로 두고, 카드를 직접 고르거나 `↺ 메뉴로` 를 누르면 메뉴로 돌아갑니다.
- 검색 방식 칩(기본·간단하게·황금레시피·1인분·에어프라이어)은 검색어 뒤에 붙습니다.
- 만개의레시피·유튜브·네이버·구글 검색 결과를 새 탭으로 엽니다. 검색 버튼(엔터)은 만개의레시피를 엽니다. 레시피 사이트는 브라우저에서 바로 부를 수 있는 공개 API 가 없어(CORS·키 필요) 링크 방식입니다.
- 최근 검색어는 `localStorage`(`what-to-eat:recipe-recent:v1`)에 최대 8개 저장합니다.

## 메뉴 추가하기

`menus.js` 에 추가합니다. 이름(`name`)은 전체에서 겹치면 안 됩니다(메뉴별 캐시 키).

분류별 `rows()` 목록에 한 줄로 넣는 방법이 간단합니다. `cuisine` 은 분류 기본값을 씁니다.

```js
// [이름, 이모지, 온도, 계절, 날씨, 끼니, 키워드, 설명, 지역]
["닭한마리", "🐔", "hot", "겨울", "cold snow", "저녁", "닭한마리", "칼국수 사리까지", "종로"],
```

- 온도 `hot` / `cold` / `""`(보통), 계절 `"가을 겨울"`(비우면 사계절), 끼니 `"점심"` / `"저녁"` / `""`(둘 다)
- 키워드는 공백으로 구분하고 첫 값이 카카오 검색어입니다. `태국`·`분식`처럼 넓은 말은 그 종류 식당이 모두 "메뉴 일치"가 되므로 넣지 않습니다.
- 맵거나 날것·내장·술안주 중심이라 아이와 먹기 어려운 메뉴면 `menus.js` 아래쪽 `NOT_KID` 목록에 이름을 넣습니다. 객체로 넣을 때는 `kid: false` 를 직접 적어도 됩니다.

세부 값이 필요하면 `MENUS` 배열에 객체로 넣어도 됩니다.

```js
{ name: "닭한마리", emoji: "🐔", cat: "한식", temp: "hot",
  seasons: ["winter"], weather: ["cold", "snow"], regions: ["종로"],
  meal: "dinner", kw: ["닭한마리"], cuisine: ["korean"], desc: "칼국수 사리까지" }
```
